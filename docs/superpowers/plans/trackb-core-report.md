# Track B core implementation report

`trackb.parser.parse_text(text, report_date)` returns text-only observation dictionaries. `parse_report(report)` adds separate deterministic questionnaire observations. Observations have the fields in the design plus `is_full_day` and `count_eligible`; `issues_json` is a list in the parser interface and JSON text in SQLite. medspaCy TargetMatcher and ConText use a small, rule-based vocabulary; they do not understand arbitrary clinical language. Dates are resolved at sentence level and explicitly multi-day claims are left undated. Unrecognized symptoms and more complex temporal or linguistic constructions can be missed or misinterpreted.

`trackb.db.connect(path)`, `initialize(conn)`, `import_dataset(conn, data_dir)`, `daily_symptoms(conn, patient_id)`, `weekly_symptoms(conn, patient_id)`, and `medication_comparison(conn, patient_id)` provide the specified interfaces. Query functions return lists of dictionaries. Daily rows cover each study-calendar date for each observed symptom, including missing reports. Questionnaire counts are the default, never added to text; conflicting full-day counts, larger partial counts, and overlapping claims are excluded. A sole explicit text count can contribute on a day without a questionnaire. Presence and report coverage remain separate from count eligibility. Comparison selects a same-day regimen stop/start and excludes the anchor day.

Four tables follow the design. `patients` adds `end_date`; `symptom_observations` adds `is_full_day` and `count_eligible`. `reports.verification_json` defaults to a not-run status and is not used by chart queries. Import reads only patients, scheduled slots, check-ins, and started/discontinued medication fixtures; stable IDs make repeat import idempotent.
